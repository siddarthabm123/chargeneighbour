## Price and reservation safeguards

- A request must carry the rate currently displayed to the driver and a supported Type 2 selection. The server checks both; a browser-only disable is not the control.
- Existing `reserve_host` serializes competing holds and snapshots the rate. The API compares the returned locked rate to the reviewed quote. If a concurrent rate change is detected, a new/confirmed request is cancelled through the existing transition RPC and a new quote is required. This is a compensating cancellation, not an atomic expected-price comparison inside the database. If a provider/database failure prevents completion, users must refresh their sessions; no automatic payment is taken.
- Host confirmation and decline require the verified Supabase identity to match the approved charger owner exactly. Driver actions remain driver-only. Service credentials are private; no email-based ownership grant is used.
- Public schedule windows disclose times only, without reservation IDs or driver identity. Raw operator evidence text is excluded. A partial schedule is explicitly labelled and every request still checks conflicts server-side.
- General-public sign-in delivery, Google content and commercial acceptance remain separately gated. Do not pitch this release as live telemetry, a safety-certified network, confirmed partner coverage or proven traction.

## Pitch wording

ChargeNeighbour helps EV drivers check connector fit, compare charging options and understand availability and price before travelling, with a reviewed neighbourhood host-sharing pilot.

Discovery safeguards are implemented. Approved hosts, actual operating performance and provider activation must be measured before claiming a commercial service.
